1. 전체 아키텍처

3개의 계층으로 구성됩니다.

[브라우저: front/*.html, *.js]
        │  fetch (JSON)
        ▼
[Flask 서버: back/server.py + controllers/*]
        │                     │
        │ JSON 파일 R/W       │ ollama.chat()
        ▼                     ▼
[back/data/calbee.json]   [Ollama: gemma2:9b]
  • Flask: 라우팅·정적 파일 서빙 (포트 5000)
  • JSON 파일: MySQL 대체. 단일 파일에 users/schedule 저장.
  • Ollama: 로컬 LLM. 채팅 메시지를 받아 JSON 명령으로 변환.

3. PY back/server.py

Flask 앱을 만들고, 각 컨트롤러(Blueprint)를 등록하고, 프론트 파일을 정적 서빙합니다.

from flask import Flask, send_from_directory
from controllers.auth import auth_bp
from controllers.schedule import schedule_bp
from controllers.chat import chat_bp

app = Flask(__name__)

# Blueprint 등록 — 라우트들을 모듈별로 분리
app.register_blueprint(auth_bp)
app.register_blueprint(schedule_bp)
app.register_blueprint(chat_bp)

# 프론트엔드 서빙
@app.route('/')
def index():
    return send_from_directory('../front', 'index.html')

@app.route('/src/<path:filename>')
def src_files(filename):
    return send_from_directory('../src', filename)

@app.route('/<path:filename>')
def static_files(filename):
    return send_from_directory('../front', filename)

if __name__ == '__main__':
    app.run(debug=True, port=5000)

학습 포인트

  • Blueprint: Flask에서 라우트들을 모듈로 묶어 관리하는 객체. auth_bp 내부에서 정의된 /api/login 등이 등록 시점에 앱에 연결됨.
  • send_from_directory: 보안상 안전하게 파일을 응답으로 내보내는 헬퍼 (디렉터리 트래버설 방지).
  • debug=True: 코드 수정 시 자동 재시작. 배포에선 끄는 게 일반적.

4. PY back/models/db.py — JSON 저장소

MySQL 대신 단일 JSON 파일을 DB처럼 사용합니다. 동시성 보호와 원자적 저장이 핵심입니다.

import json
import os
from threading import Lock

BASE_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
DATA_DIR = os.path.join(BASE_DIR, 'data')
DB_PATH  = os.path.join(DATA_DIR, 'calbee.json')

_lock = Lock()  # 동시 요청이 같은 파일을 망가뜨리지 않도록

_DEFAULT = {
    "meta": {"next_user_code": 1, "next_scd_no": 1},
    "users": [],
    "schedule": []
}

def _ensure_file():
    if not os.path.exists(DATA_DIR):
        os.makedirs(DATA_DIR, exist_ok=True)
    if not os.path.exists(DB_PATH):
        with open(DB_PATH, 'w', encoding='utf-8') as f:
            json.dump(_DEFAULT, f, ensure_ascii=False, indent=2)

def load_db():
    _ensure_file()
    with open(DB_PATH, 'r', encoding='utf-8') as f:
        return json.load(f)

def save_db(data):
    _ensure_file()
    tmp = DB_PATH + '.tmp'
    with open(tmp, 'w', encoding='utf-8') as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    os.replace(tmp, DB_PATH)  # 원자적 교체 — 쓰다가 중단돼도 본 파일 안전

def with_db(fn):
    """데코레이터: load → 함수 실행 → save 를 자동 처리."""
    def wrapper(*args, **kwargs):
        with _lock:
            data = load_db()
            result = fn(data, *args, **kwargs)
            save_db(data)
            return result
    return wrapper

학습 포인트

  • Lock: Flask는 기본적으로 여러 요청을 동시에 처리할 수 있음. 두 요청이 같은 시점에 파일을 쓰면 깨질 수 있으므로 with _lock:으로 한 번에 하나씩만 진입.
  • 원자적 저장: tmp 파일에 먼저 쓴 뒤 os.replace로 갈아끼우면, 쓰는 도중 정전/오류가 나도 기존 파일이 손상되지 않음.
  • 데코레이터: @with_db를 붙이면 함수의 첫 인자로 data가 자동으로 들어오고, 함수가 끝나면 자동으로 저장됨. 반복 코드 제거.
  • ensure_ascii=False: 한글이 \uXXXX로 인코딩되지 않고 그대로 저장되어 읽기 편함.

5. PY back/models/user.py

from models.db import with_db
from datetime import date

@with_db
def find_user(data, user_id):
    for u in data['users']:
        if u['USER_ID'] == user_id:
            return u
    return None

@with_db
def create_user(data, user_id, user_pw):
    if any(u['USER_ID'] == user_id for u in data['users']):
        return False  # 중복 ID
    code = data['meta']['next_user_code']
    data['meta']['next_user_code'] = code + 1   # auto-increment 흉내
    data['users'].append({
        "USER_CODE":  code,
        "USER_ID":    user_id,
        "USER_PW":    user_pw,
        "CREATED_AT": str(date.today()),
        "USER_GRANT": 2
    })
    return True

학습 포인트

  • @with_db 덕분에 함수 안에서는 순수 파이썬 리스트 조작만 하면 됨. 파일 입출력은 데코레이터가 처리.
  • meta.next_user_code: SQL의 AUTO_INCREMENT를 흉내낸 카운터.

6. PY back/models/schedule.py

from models.db import with_db
from datetime import date

def _to_int(v):
    try: return int(v)
    except (TypeError, ValueError): return v

@with_db
def get_schedules(data, usercode):
    uc = _to_int(usercode)
    return [dict(s) for s in data['schedule'] if s['USER_CODE'] == uc]

@with_db
def insert_schedule(data, usercode, title, scd_date, description):
    scd_no = data['meta']['next_scd_no']
    data['meta']['next_scd_no'] = scd_no + 1
    today = str(date.today())
    data['schedule'].append({
        "USER_CODE":   _to_int(usercode),
        "SCD_NO":      scd_no,
        "SCD_TITLE":   title,
        "SCD_DATE":    str(scd_date),
        "SCD_TIME":    None,
        "DESCRIPTION": description,
        "CREATED_AT":  today,
        "UPDATED_AT":  today
    })

@with_db
def remove_schedule(data, scd_no, usercode):
    uc = _to_int(usercode); sn = _to_int(scd_no)
    data['schedule'] = [
        s for s in data['schedule']
        if not (s['SCD_NO'] == sn and s['USER_CODE'] == uc)
    ]

학습 포인트

  • 왜 _to_int? 프론트의 쿼리스트링(?usercode=3)은 문자열로 들어옴. JSON에 저장된 값은 정수. 비교가 깨지지 않도록 통일.
  • dict(s)로 복사본 반환: 외부에서 결과를 수정해도 원본 JSON에 영향이 가지 않게.
  • 삭제는 리스트 컴프리헨션으로 조건에 맞는 항목만 빼고 새 리스트로 교체.

7. PY back/models/ai.py — Ollama 호출

import ollama

MODEL = 'gemma2:9b'

def chat_json(system_prompt, user_message):
    res = ollama.chat(
        model=MODEL,
        messages=[
            {'role': 'system', 'content': system_prompt},
            {'role': 'user',   'content': user_message}
        ],
        format='json'   # ← 응답을 반드시 JSON 형식으로 강제
    )
    return res['message']['content']

학습 포인트

  • system 메시지: 모델의 역할/규칙을 지정. user 메시지: 사용자의 실제 입력.
  • format='json': Ollama의 강력한 기능. 모델이 잡담을 섞지 않고 JSON 객체만 반환하도록 디코더를 제약.
  • 스트리밍을 끈 이유: 응답을 파싱해서 액션을 실행해야 하므로 전체가 다 와야 함.

8. PY back/controllers/auth.py

from flask import Blueprint, request, jsonify
from models import user as UserModel

auth_bp = Blueprint('auth', __name__)

@auth_bp.post('/api/login')
def login():
    data   = request.json
    result = UserModel.find_user(data['id'])

    if result is None:
        return jsonify({"success": False, "message": "존재하지 않는 아이디입니다."})
    elif result['USER_PW'] == data['pw']:
        return jsonify({"success": True, "usercode": result['USER_CODE'], "grant": result['USER_GRANT']})
    else:
        return jsonify({"success": False, "message": "비밀번호가 틀렸습니다."})

@auth_bp.post('/api/signup')
def signup():
    data    = request.json
    success = UserModel.create_user(data['id'], data['pw'])
    if success:
        return jsonify({"success": True, "message": "계정이 생성되었습니다."})
    else:
        return jsonify({"success": False, "message": "중복되는 아이디가 존재합니다."})
실무 주의: 비밀번호를 평문으로 비교하고 있습니다. 실제 서비스라면 bcrypt 같은 해시 함수로 저장해야 합니다. 학습용 과제 수준이라 단순화한 상태입니다.

9. PY back/controllers/schedule.py

from flask import Blueprint, request, jsonify
from models import schedule as ScheduleModel

schedule_bp = Blueprint('schedule', __name__)

@schedule_bp.get('/api/schedules')
def get_schedules():
    usercode = request.args.get('usercode')   # 쿼리스트링
    return jsonify(ScheduleModel.get_schedules(usercode))

@schedule_bp.post('/api/schedules')
def add_schedule():
    data = request.json
    ScheduleModel.insert_schedule(
        data['usercode'], data['title'],
        data['date'], data.get('description', '')
    )
    return jsonify({"success": True, "message": "일정이 추가되었습니다."})

@schedule_bp.delete('/api/schedules/<int:scd_no>')
def delete_schedule(scd_no):
    usercode = request.args.get('usercode')
    ScheduleModel.remove_schedule(scd_no, usercode)
    return jsonify({"success": True, "message": "일정이 삭제되었습니다."})

학습 포인트

  • HTTP 메서드별 데코레이터: @bp.get, @bp.post, @bp.delete — RESTful 스타일.
  • <int:scd_no>: URL 경로의 일부를 정수로 받아 함수 인자로 전달.
  • request.args(쿼리스트링) vs request.json(body) 차이.

10. PY back/controllers/chat.py — LLM 툴 콜링 ⭐

이 프로젝트의 핵심. 자연어 메시지를 받아서 LLM에게 JSON 명령으로 변환시키고, 그 명령에 따라 일정 모델을 실제로 호출합니다.

import json
from datetime import date
from flask import Blueprint, request, jsonify
from models import ai as AIModel
from models import schedule as ScheduleModel

chat_bp = Blueprint('chat', __name__)

SYSTEM_TEMPLATE = """너는 'cal-bee'라는 한국어 일정 관리 비서다.
사용자의 메시지를 보고 의도를 분류해 **JSON 한 개**로만 응답한다.

오늘 날짜: {today}

사용자의 현재 일정 목록:
{schedules}

응답 스키마:
{{
  "action": "add" | "delete" | "list" | "chat",
  "title": "...",
  "date": "YYYY-MM-DD",
  "description": "...",
  "scd_no": 정수,
  "reply": "한국어 답변 (항상 필수)"
}}
..."""

시스템 프롬프트에 오늘 날짜와 현재 일정 목록을 포함하는 것이 핵심입니다. 모델이 "내일", "치과 일정"같은 표현을 정확한 날짜·SCD_NO로 변환할 수 있게 됩니다.

def _build_system_prompt(schedules):
    if not schedules:
        sched_text = "(없음)"
    else:
        lines = [
            f"- SCD_NO={s['SCD_NO']}, 제목='{s['SCD_TITLE']}', "
            f"날짜={s['SCD_DATE']}, 설명='{s.get('DESCRIPTION', '')}'"
            for s in schedules
        ]
        sched_text = "\n".join(lines)
    return SYSTEM_TEMPLATE.format(today=date.today().isoformat(), schedules=sched_text)


def _safe_parse(raw):
    """모델이 JSON을 약간 어겼을 때를 위한 폴백 파서."""
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        start = raw.find('{'); end = raw.rfind('}')
        if start != -1 and end > start:
            try: return json.loads(raw[start:end + 1])
            except json.JSONDecodeError: return None
        return None


@chat_bp.post('/api/chat')
def chat():
    body     = request.json or {}
    question = (body.get('question') or '').strip()
    usercode = body.get('usercode')

    if not question:
        return jsonify({"reply": "메시지를 입력해 주세요.", "refresh": False})
    if not usercode:
        return jsonify({"reply": "로그인이 필요합니다.", "refresh": False})

    # 1) 현재 일정을 컨텍스트로 모델에게 전달
    schedules = ScheduleModel.get_schedules(usercode)
    system    = _build_system_prompt(schedules)

    # 2) LLM 호출 → JSON 응답
    raw    = AIModel.chat_json(system, question)
    parsed = _safe_parse(raw)
    if not parsed:
        return jsonify({"reply": "죄송해요, 이해하지 못했어요.", "refresh": False})

    action = parsed.get('action', 'chat')
    reply  = parsed.get('reply') or '처리했어요.'

    # 3) 액션 분기 — 실제 일정 모델을 호출
    if action == 'add':
        title    = parsed.get('title')
        scd_date = parsed.get('date')
        desc     = parsed.get('description', '') or ''
        if not title or not scd_date:
            return jsonify({"reply": "일정 제목과 날짜를 알려 주세요.", "refresh": False})
        ScheduleModel.insert_schedule(usercode, title, scd_date, desc)
        return jsonify({"reply": reply, "refresh": True})

    if action == 'delete':
        scd_no = parsed.get('scd_no')
        if scd_no is None:
            return jsonify({"reply": "어떤 일정을 삭제할지 알려 주세요.", "refresh": False})
        ScheduleModel.remove_schedule(scd_no, usercode)
        return jsonify({"reply": reply, "refresh": True})

    return jsonify({"reply": reply, "refresh": False})
이 기법의 이름: "Tool calling" 또는 "Function calling"입니다. 큰 회사의 LLM API(OpenAI, Anthropic 등)는 전용 기능으로 제공하지만, 로컬 모델인 gemma2에선 프롬프트로 강제 + JSON 모드로 직접 구현한 것입니다.

학습 포인트

  • 모델은 판단만 하고, 실행은 파이썬이 한다 — 안전한 패턴.
  • 일정 목록을 매번 프롬프트에 넣는 것은 비효율적이지만, 데이터가 적은 학습용에선 충분.
  • refresh: True를 응답에 넣어 프론트가 일정 목록을 다시 불러오게 트리거.

11. JS 프론트엔드 핵심

api.js — fetch 래퍼

export async function sendChat(usercode, question) {
    const res = await fetch('/api/chat', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ usercode, question })
    });
    return res.json();
}

12. 데이터 흐름 시나리오

시나리오 A: "내일 동아리 회의 잡아줘"

  1. 브라우저 app.js: sendChat(usercode, "내일 동아리 회의 잡아줘") 호출
  2. POST /api/chat → chat.py 진입
  3. ScheduleModel.get_schedules(usercode) — 현재 일정 조회
  4. 시스템 프롬프트 구성 (오늘 날짜 + 일정 목록 + 스키마)
  5. ollama.chat(format='json') 호출 → 모델이 {"action":"add","title":"동아리 회의","date":"2026-05-31","reply":"내일 동아리 회의 일정을 추가했어요."} 반환
  6. action=="add" → insert_schedule(...) → JSON 파일에 추가
  7. 응답: {"reply":"...추가했어요", "refresh":true}
  8. 프론트: 메시지 표시 + loadSchedules()로 일정 패널 갱신

시나리오 B: "치과 일정 지워줘"

  1. POST /api/chat
  2. 현재 일정 목록 안에 SCD_NO=5, 제목='치과 예약'이 있다면 모델이 {"action":"delete","scd_no":5,"reply":"치과 일정을 삭제했어요."} 반환
  3. remove_schedule(5, usercode) 호출
  4. 응답에 refresh:true → 일정 목록 새로고침

13. 핵심 개념 정리

개념설명이 프로젝트에서
BlueprintFlask에서 라우트를 모듈로 묶는 객체auth_bp, schedule_bp, chat_bp
데코레이터함수를 감싸 부가 동작 추가@with_db — load/save 자동화
스레드 락동시 접근으로 인한 데이터 손상 방지_lock이 JSON 파일 쓰기 직렬화
원자적 쓰기tmp 파일 → rename으로 중단 시에도 안전os.replace(tmp, DB_PATH)
시스템 프롬프트모델의 역할/규칙을 지정하는 메시지SYSTEM_TEMPLATE
JSON 모드모델이 JSON만 출력하도록 디코더 제약format='json'
툴 콜링LLM이 함수 호출을 결정, 코드가 실행action 분기 → ScheduleModel 호출
관심사 분리역할별 파일/모듈 분리controllers / models / front 분리
실행 방법 복습 
pip install -r requirements.txt
ollama pull gemma2:9b
python back/server.py
# 브라우저에서 http://localhost:5000
